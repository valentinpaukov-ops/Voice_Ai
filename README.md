# Voice_Ai

**Корпоративное радио «Технологии Доверия»**

Первая площадка компании, где контент об искусственном интеллекте создан с помощью
нейросетей: ИИ-эфиры, подкасты, разборы технологий, новости и обучающие материалы.

| | |
|---|---|
| **Адрес** | https://valentinpaukov-ops.github.io/Voice_Ai/ |
| **Репозиторий** | `valentinpaukov-ops/Voice_Ai` |
| **Хостинг** | GitHub Pages, статическая страница без сервера и базы данных |
| **Редакция** | info@tedo.ru |

## Как всё устроено

Весь сайт — это **один файл** `index.html`. В нём и вёрстка, и стили, и логика:
ни сборки, ни сервера, ни внешних библиотек. Данные лежат рядом в двух текстовых
файлах, и страница читает их при открытии.

```
index.html                              сам сайт
lame.min.js                             кодировщик MP3 для сжатия в браузере
audio/                                  аудиозаписи
  manifest.json                         фонотека + программа эфира по дням
news/
  news.json                             новости
.github/workflows/
  build-manifest.yml                    робот, который ведёт фонотеку
```

Такая конструкция означает, что сайт невозможно «уронить»: нечему падать.
Обратная сторона — всё, что мы храним, лежит в репозитории и занимает место.

## Что видит слушатель

### Эфир

Открыл страницу — эфир уже идёт. Плеер умеет паузу, перемотку, переход к следующей
и предыдущей записи, громкость и полное выключение звука. Рядом с записью
показывается её описание, и оно меняется вместе с треком. Если закрыть вкладку и
вернуться, воспроизведение продолжится с того места, где вы остановились.

> **Про автозапуск со звуком.** Ни один браузер не разрешает включить звук до
> первого действия человека на странице — это защита от кричащей рекламы, обойти
> её нельзя. Страница делает всё, что возможно: запускается сразу, как только
> браузер даёт добро, и подхватывает эфир с первого же клика или прокрутки.

### История эфиров

Под очередью — лента дней: сплошной ряд дат, по которому можно листать в обе
стороны стрелками, колесом мыши или пальцем. Кнопка **«Сегодня»** появляется,
только когда текущий день уехал из вида, и возвращает ленту на место.

Цветные точки под датой говорят, что в этот день было:

| Точка | Значит |
|---|---|
| 🔵 синяя | в этот день был эфир |
| 🟣 фиолетовая | в этот день выходили подкасты или шоу |
| 🩵 голубая | в этот день выходили новости |
| пунктир без точек | день ещё не наступил |

Цифры дней в ленте — оранжевые. Под лентой, как и под календарём архива, висит
легенда: «эфир», «подкасты / шоу», «новости».

**Закрыт от поисковых систем.** На обеих страницах (`index.html`, `docs/news-sender.html`) стоит мета-тег
`<meta name="robots" content="noindex, nofollow, noarchive, nosnippet, noimageindex">`. Он работает всегда, но только для
страниц, а не для файлов `.md` и `.json`. Файл `robots.txt` (запрещает обход всем роботам, включая ИИ-краулеры) для проектного
сайта вида `…github.io/Voice_Ai/` должен лежать **в корне домена** `valentinpaukov-ops.github.io`, то есть в репозитории
`valentinpaukov-ops.github.io`, а не в Voice_Ai: из подпапки поисковики его не читают. Ограничения: это просьба к добросовестным
роботам, а не технический запрет; страница остаётся открытой для всех, у кого есть ссылка; а публичный репозиторий на github.com
индексируется GitHub независимо от этого сайта. Если сайт уже в выдаче Google, не закрывайте его `robots.txt` сразу: робот
тогда не увидит `noindex` и оставит адрес в выдаче. Сначала дождитесь, когда `noindex` будет прочитан (или удалите адреса
через Search Console), и только потом ставьте `robots.txt`.

**Новости: независимые маршруты.** Новость попадает на сайт одним из способов, и каждый работает сам по себе: отказ или
отсутствие любого другого на него не влияет (нужен только репозиторий).

| № | Маршрут | Кто | Что нужно | Попадает на сайт |
|---|---|---|---|---|
| 1 | Правка файла `news/news.json` на GitHub | выпускающий | доступ к репозиторию | сразу |
| 2 | Форма одной новости на платформе (`?admin=1`, «+ Добавить новость») | выпускающий | токен в режиме редактора | сразу |
| 3 | Форма загрузки на платформе (кнопка «Загрузить новости (Word, JSON, текст)») | выпускающий | токен в режиме редактора | сразу или через согласование |
| 4 | Страница `docs/news-sender.html?chief=1` | выпускающий | токен | сразу или через согласование |
| 5 | Страница `docs/news-sender.html` у редактора (код доступа вверху) | редактор | адрес страницы и код доступа | после согласования выпускающим |
| 6 | Файл от редактора (кнопка «Скачать файл») открывает выпускающий | редактор → выпускающий | ничего у редактора | сразу или через согласование |
| 7 | Готовый JSON кладут в `inbox/` на GitHub (по файлу на новость или пачкой) | кто угодно с доступом | доступ к репозиторию | после согласования выпускающим |
| 8 | Агент пишет JSON в `inbox/` сам (если у него есть доступ) | агент | токен у агента | после согласования выпускающим |

Общее у всех маршрутов только формат записи новости и очередь `inbox/` (маршруты 5–8): выпускающий видит её на платформе в блоке «на согласовании».

**Сломанный `news/news.json`.** Файл можно править руками, но одна потерянная запятая ломает его целиком. Тогда слушатели
видят запасные старые новости, а выпускающий (режим редактора) видит красный баннер: что сломано, около какой строки, что
вероятнее всего не так (пропущена или лишняя запятая, оборван файл) и ссылку «Открыть news.json на GitHub».

**Массовые действия в очереди.** В блоке «на согласовании» у каждой новости есть галочка (панель действий появляется, когда
в очереди две новости и больше). Кнопки «Опубликовать выбранные» и «Отклонить выбранные» работают сразу со всем отмеченным,
«Выбрать все новости» отмечает всё. Публикация идёт **одной записью в `news/news.json`**, решение по каждой новости
принимается по свежему списку из репозитория: если в очереди стоит пометка замены и опубликованная новость на месте,
она заменяется на месте (прежние дата и время сохраняются, отпечатки объединяются); иначе добавляется новой. Новость,
которая один в один похожа на уже опубликованную, пропускается и остаётся в очереди, если редактор не выбрал в форме «как
новую» (это выбор записывается в файл очереди полем `asNew`); пропускаются также новость без заголовка и вторая замена
одной и той же опубликованной новости. Перед публикацией платформа показывает, сколько будет опубликовано, замен, новостей с датой в будущем и что пропущено.
После публикации файлы опубликованных убираются из очереди (из пачки только их записи); если убрать не удалось, платформа
говорит об этом, а повторный запуск такую новость не дублирует.

**Пачка в `inbox/`.** Файл в `inbox/` может быть и пачкой: тем самым JSON, что отдаёт агент (`{"agent": …, "news": […]}`),
или просто массивом. Каждая новость показывается отдельной карточкой; публикация или отклонение убирают из файла только её,
а когда в пачке никого не осталось, файл удаляется сам. Обычные файлы «по одной новости» работают как раньше.

**Загрузка новостей внутри платформы.** В режиме редактора рядом с «+ Добавить новость» стоит кнопка «Загрузить новости (Word,
JSON, текст)». Она открывает поверх платформы ту же страницу `docs/news-sender.html` в режиме выпускающего (токен подставляется
сам, потому что адрес тот же). После публикации или отправки на согласование страница сообщает платформе, и лента и очередь
обновляются без перезагрузки.

**Новости от агента (папка `inbox/`).** Корпоративный агент (Тедора) готовит новости из документа Word и
отдаёт обычный текст: один JSON со списком новостей. Страницы с кнопкой агент не делает. Страница-отправщик
живёт в репозитории как постоянный инструмент: `docs/news-sender.html`, адрес
`https://valentinpaukov-ops.github.io/Voice_Ai/docs/news-sender.html`. Редактор открывает её, вставляет JSON в
поле (или выбирает файл) и нажимает «Разобрать»: страница находит JSON даже внутри пояснений и блока кода,
лишние запятые исправляет сама, а при настоящей ошибке объясняет, что не так, и ничего не загружает частично.
JSON вставляется кнопкой «Вставить из буфера» или Ctrl+V и разбирается сам. Карточки можно править, лишние
отключить. Токен GitHub подставляется из редактора сайта (страница лежит на том же адресе) или вводится один
раз. Есть два действия. «Опубликовать на сайте» после подтверждения пишет проверенные новости прямо в
`news/news.json` (замена правит опубликованную новость на месте, новая добавляется; при конфликте записи
страница сама повторяет; ничего не пишется, если токен не принят). «Отправить на согласование» кладёт в `inbox/`
по файлу JSON на каждую
новость (`kind: "news"`, поля `title`, `text`, `date`, `time`, `author`, `tags`, необязательные `sourceName`,
`sourceUrl`, `important`, а также `agent`, `created`, `fp`). Слушателям эти файлы не видны и на сайт сами не
попадают: в режиме редактора (`?admin=1`) появляется блок «на согласовании», у каждой новости «Проверить»
открывает форму, «Опубликовать» выпускает. Опубликованную новость файл из очереди убирает. Агент в
`news/news.json` не пишет никогда. Текст промпта для агента: `docs/agent-news-prompt.md`.

Дубли и обновления. Страница-отправщик сама читает опубликованные новости (с сайта, токен не нужен) и для
каждой карточки ищет такую же или похожую: сравниваются заголовок, текст и ссылка на источник, правки
слов, знаков препинания и даты не мешают. Если нашла, человек выбирает «заменить опубликованную»
(с показом «было / стало»; по умолчанию сохраняются дата и время опубликованной) или «отправить как
новую». У замены в файле очереди есть поля `replaces` (id опубликованной новости) и `replacesTitle`.
На платформе «Проверить» у такой новости открывает форму опубликованной, с блоком «было / станет», а
кнопка называется «Заменить опубликованную новость»: вторая новость не появляется. Если опубликованной уже
нет (удалили), публикуется как новая. Если пометки нет, но на сайте уже есть похожая, платформа при
«Проверить» предупредит и предложит заменить её одним нажатием. Алгоритм сравнения (`nmCompare`) один и тот
же на сайте и на странице-отправщике; на 31 новости сайта он не принял ни одну пару разных новостей за
похожие и узнал правленые версии в 30–31 случаях из 31.

**Готовая форма для сотрудника (основной способ для редакторов).** Выпускающий на платформе (режим редактора → «Доступ для
редакторов») вставляет токен, ограниченный отдельным репозиторием очереди, при желании вписывает имя сотрудника и нажимает «Скачать
готовую форму». Платформа собирает из `docs/news-sender.html` файл, в котором ключ уже встроен (`window.EDITOR_PRESET` в начале
страницы), и записывает адрес очереди в `docs/news-sender-access.json`. Сотрудник открывает файл двойным щелчком: форма сразу
активирована, режим редактора, имя подставлено. Он вставляет текст, JSON или файл Word, форма раскладывает его по карточкам,
подсказывает теги, ищет дубли; кнопка «Отправить на проверку» кладёт новости в репозиторий очереди. Платформа читает адрес очереди
из репозитория напрямую (через API, без ожидания публикации сайта) и показывает присланное в блоке «на согласовании». Файл формы
нельзя выкладывать на сайт или в репозиторий: ключ лежит внутри. Ключ даёт право только добавлять файлы в очередь; публиковать новости
и менять сайт им нельзя. Отключить все выданные формы сразу можно, отозвав токен очереди на GitHub.

**Редакторы новостей (ручной маршрут).** Та же страница работает и для людей, наравне с агентом, и **редакторам не нужен
GitHub**: никого никуда добавлять не требуется. Редактор открывает единый адрес, вводит выданный выпускающим код доступа
и отправляет новости на проверку. Принимается: файл Word (.docx; читается прямо в браузере, без сервера), JSON от агента
или обычный текст. Из Word и текста страница нарезает карточки: по заголовкам (стили «Заголовок» или короткие жирные
строки), по пустым строкам, по абзацам, по пунктам списка или по строкам таблицы; способ выбирается автоматически и
переключается в списке. Дальше: тот же разбор дублей и замен, дата, время, автор, а теги подсказываются автоматически
(по тегам самых похожих опубликованных новостей и по словам текста; на 31 опубликованной новости подсказка даёт точность
около 71% и хотя бы один верный тег в 25 случаях из 31, поэтому редактор их проверяет). Есть кнопки «+ Добавить новость»
(написать вручную), «слить с предыдущей», «удалить», «Расставить время по порядку».

Как новости попадают на платформу без токена редактора. Ключ для редакторов (токен GitHub, ограниченный **отдельным
репозиторием очереди**, например `Voice_Ai_inbox`) лежит в файле `docs/news-sender-access.json` только в зашифрованном виде:
AES-GCM, ключ выводится из кода доступа через PBKDF2 (600 000 кругов). Файл создаёт платформа: режим редактора → «Доступ для
редакторов» (токен, имя репозитория очереди, код; код генерируется длинным и случайным). Редактор вводит код вверху формы и
нажимает «Активировать»: форма расшифровывает ключ в браузере (самого токена редактор не видит), после чего отправка пишет файлы
`inbox/news-<партия>-<номер>.json` в репозиторий очереди. Платформа читает очередь из обоих мест (основной `inbox/` и репозиторий
очереди) и показывает всё в блоке «на согласовании»; публикация, отклонение и пачки работают одинаково. Если токен выпускающего не
видит репозиторий очереди, платформа говорит об этом в блоке «на согласовании». Повторная отправка той же партии перезаписывает
файлы, а не множит. Подпись «от <имя>» редактор вписывает сам (подпись не проверяется; для 1–2 доверенных людей этого достаточно).
Настройка и безопасность (почему нельзя короткий код вроде «admin», как отозвать доступ): `docs/access-setup.md`.

Пока доступ не настроен, у редактора вместо отправки работают кнопки «Скачать файл для выпускающего» и «Скопировать для
выпускающего»: выпускающий открывает такой файл на платформе через «Загрузить новости».

Роли задаются адресом: обычный адрес даёт режим редактора (поле «Код доступа», кнопка «Опубликовать на сайте» скрыта),
адрес с `?chief=1` включает режим выпускающего (поле токена GitHub, публикация сразу; запоминается в браузере, `?chief=0`
выключает). Защита построена не на скрытой кнопке: у редактора нет токена выпускающего, а ключ редакторов позволяет писать
только в репозиторий очереди. Инструкция для редакторов: `docs/instruction-news-editors.md`.

Правила выбора по умолчанию: «заменить опубликованную» стоит, только когда это та же новость целиком; если новая
лишь часть опубликованной или объединяет несколько, по умолчанию «как новая», чтобы не урезать и не смешать
опубликованное. Две новости одной партии не могут заменять одну и ту же опубликованную: страница остановит
отправку и скажет, у каких. Агент работает в двух режимах: «из документа» и «дайджест из интернета» (там
обязательны ссылка на статью и дословный фрагмент; текст пишется своими словами, чтобы не публиковать чужой
текст целиком); подробности в `docs/agent-news-prompt.md`.

**Узнавание новости, пересказанной по-другому.** Агент генерирует текст заново при каждом запуске, поэтому
слова одной и той же новости могут сильно отличаться. Чтобы это не мешало, агент в каждой новости
присылает `origin` — дословный фрагмент документа, из которого она сделана. Страница-отправщик
вычисляет из него отпечаток `fp` (хеши пар соседних слов; самого текста документа в репозитории нет,
потому что репозиторий публичный) и кладёт в очередь. При публикации `fp` попадает в `news.json` (поле `fp`,
в среднем около 30 коротких кодов), и дальше новость узнаётся по исходному тексту, как бы её ни пересказали.
Если исходник новости совпадает с опубликованной на 40% и больше, она считается той же; страница и платформа
отдельно предупреждают, если новая — часть опубликованной или объединяет её с другим материалом.
У новостей, опубликованных до введения `fp`, сверка идёт только по словам: отпечаток для них не восстановить.
При ручной правке новости в редакторе `fp` сохраняется, при замене объединяется со старым.
Сам файл очереди (`inbox/`) лежит в публичном репозитории, хотя на сайте слушателям не виден: не кладите туда
ничего, что нельзя показывать посторонним.

**Срок жизни записи.** У записи фонотеки может быть необязательное поле «Показывать до»
(дата и время по Москве; если время не указано — до конца дня). Оно есть в форме загрузки и
в правке записи и хранится в `audio/manifest.json` как `expires`, например
`"expires": "2026-10-15T18:00"`. Робот это поле сохраняет. Правила:
- после срока запись пропадает из фонотеки для слушателей (страницы подкастов, шоу,
  гайдов, превью на главной, поиск) и не ставится в новые эфиры;
- срок считается от дня эфира: из прошедших дней (эфиры и архив) запись не убирается,
  из сегодняшнего эфира она уходит в момент срока, день в будущем принимает её, если срок
  не кончается раньше, чем день начнётся;
- страница, открытая в момент срока, сама убирает запись (проверка раз в полминуты; то, что
  играет прямо сейчас, не прерывается, пока не закончится выбранная запись);
- «Повторить прошлый эфир» и «Взять за основу» не переносят записи с истёкшим сроком
  и говорят, сколько пропущено; одна запись стоит в дне только один раз;
- редактор видит просроченные записи всегда: с красной плашкой «срок истёк», в очереди — с
  подписью, что слушатели её не видят. В «Взять из фонотеки» кнопка у такой записи называется
  «продлить и в эфир»: программа предлагает продлить срок до конца выбранного дня;
- файл не удаляется, запись только скрывается: вернуть её можно, сняв или продлив срок в правке;
- виджет на чужих сайтах соблюдает те же правила.
Срок пока есть только у записей фонотеки; у текстовых новостей и анонсов его нет.

**Подпись «повтор от …».** Если запись впервые выходила раньше дня, в очереди у неё
стоит «повтор от 21 сентября». Это настраивается при сборке эфира (только в режиме
редактора): у каждой повторяющейся записи в очереди есть галочка «повтор» — снимите её,
и слушатели подпись у этой записи не увидят; над очередью, в панели сборки, есть общая галочка
«Подписывать повторы» на весь день (она показывает общее состояние: все, никто или часть).
По умолчанию подпись пишется, как и раньше. Настройка хранится в манифесте:
`"repeatHide": {"2026-10-01": ["файл.mp3"]}` — файлы дня, у которых подпись скрыта. «Повторить
прошлый эфир» и «Взять за основу» переносят эту настройку вместе с записями. Робот
(`build-manifest.yml`) сохраняет ключ `repeatHide` и убирает из него записи, которых в дне уже нет.

**«Сегодня» считается по Москве**, как и часы в шапке, а не по часам устройства слушателя.
Лента дней при открытии всегда стоит на сегодняшнем числе (справа остаются пара дней
вперёд). Если на сегодня эфир ещё не собран, под лентой написано «На сегодня эфир ещё не
собран — играет эфир от …», и играет последний доступный. Страница может простоять открытой
за полночь: когда по Москве наступает новая дата, лента сама переезжает на неё, а если в
этот момент ничего не играло и стоял вчерашний эфир, открывается сегодняшний. Играющее
не прерывается.

Нажатие на день всегда открывает **архив** на этой дате — слушать запускают уже
оттуда. Так у любого дня одно и то же поведение, без исключений.

### Архив

Календарь по месяцам, где дни с материалами помечены теми же точками. Выбранный
день раскрывается в две колонки: слева **Эфир этого дня**, справа **Новости этого
дня**, ниже — **Подкасты / шоу этого дня**. Заголовки колонок окрашены в цвет
своей точки. Можно включить весь выпуск целиком или любую отдельную запись.

### Новости

Три свежие новости на главной, остальные — на своей странице. У каждой заголовок,
дата и время (оранжевые), текст, автор, теги и ссылка на источник. Важные
помечены вертикальной синей полосой.

### Поиск, фильтры, сортировка

Поиск идёт по всему сразу: эфиру, новостям, подкастам, шоу, гайдам — по названиям,
описаниям, авторам и тегам. На страницах разделов можно фильтровать по нескольким
тегам одновременно и сортировать: новые→старые, старые→новые, А→Я, Я→А.

### Оформление

Тёмная тема по умолчанию, переключатель на светлую — в шапке. Выбор запоминается.
Ссылки внутри любых описаний становятся кликабельными и подсвечиваются светло-синим.
Вёрстка проверена на ширинах от 360 до 1920 пикселей.

#### Фирменные цвета

**Фон страницы** — градиент, закреплённый за окном (он не растягивается на длинных

Задаётся двумя переменными в каждой теме: `--canvas` (основа) и `--page-bg`
(градиент). В тёмной теме — наш `#131319` и два мягких синих свечения по углам
(`#0048f4` справа сверху, `#000f9b` слева снизу); в светлой — белый с лёгкой
голубизной `#92b6fd` к правому нижнему углу. Поменять силу или цвет свечения можно

Фоны карточек, рамки и серый второстепенный текст пока свои, не из палитры. В палитре
для них есть серые `#3c414b`, `#6d7c8c`, `#c8cddc`.

**Эквалайзер в большом плеере** (семь полосок под кнопками) ведётся по реальному звуку:
анализатор Web Audio делит спектр на семь полос (от басов к верхам), и каждая полоска
повторяет громкость своей полосы. Каждая полоса подстраивается под себя, поэтому и
тихие, и громкие записи занимают всю высоту, а высокие частоты, которых в музыке всегда
меньше, тоже двигаются. Подъём быстрый, спад плавный. На беззвучии (громкость 0)
полоски ложатся. Полоски не зависят от положения ползунка громкости.
Пока звук не идёт через Web Audio (например, при автозапуске без касания страницы)
полоски живут на запасной CSS-анимации: три рисунка, которые сменяются по кругу от записи
к записи. Скорость запасной анимации задаёт `--vu-k` в блоке `.vu`. Режим «по звуку»
выключается одной строкой `var VU_FROM_AUDIO = false;` в `index.html`.

основного синего: `#92b6fd` в тёмной теме и `#0048f4` в светлой (переменная
`--brand-ai`). Логотип в тёмной теме белый, в светлой чёрный (переменная `--logo`):

и **встроен прямо в `index.html`** (блок `.tedo-logo` в начале страницы), поэтому шапка
не зависит от внешних адресов. Если логотип обновится — замените SVG в этом блоке
(контуры должны быть с `fill="currentColor"`). Логотип скрывается там, где не хватает
места: от 861 до 1080 px и на телефонах уже 440 px.

`#92b6fd`, `#3c6df4`.

обложки сайт и виджет добавляют метку версии (`?v=…`), чтобы браузеры не
показывали старую картинку из кэша. Метка меняется сама при любой правке через
редактор. **Если заменили файл обложки вручную на GitHub** под тем же именем —
увеличьте `COVER_REV` на единицу в двух местах: в `index.html` и в `widget.js`. Картинка для карточки
ссылки в мессенджерах — `covers/og-image.jpg` (1200×630); текст карточки задаётся
тегами `description`, `og:` и `twitter:` в начале `index.html`.

## Что может редактор

Режим редактора включается один раз адресом с добавкой `?admin=1` и запоминается
в этом браузере до `?admin=0`. Всё, что описано ниже, обычному слушателю не видно
и недоступно.

> **Про безопасность честно.** Режим редактора — это удобство, а не защита:
> страница статическая, и любой может дописать `?admin=1` и увидеть формы. Но
> толку от этого нет: без токена GitHub формы ничего не публикуют. Настоящий ключ
> от эфира — токен, и он лежит только в вашем браузере, а не в коде страницы.

### Фонотека и программа эфира

Это главная идея всей системы, и её стоит понять один раз.

**Фонотека** — всё, что когда-либо загружали: эфиры, подкасты, шоу, гайды, музыка.
У каждой записи есть дата первой публикации, и она больше никогда не меняется.

**Программа эфира** — отдельный список на каждый день: «двадцать пятое: вот эти
записи в таком порядке».

Одна и та же запись может стоять в скольких угодно днях, в каждом на своём месте,
**файл при этом остаётся один**. Никакого дублирования, никакого расползания
описаний, никакого лишнего места в репозитории.

```json
{
  "tracks": [
    { "file": "digest.mp3", "title": "Дайджест новостей",
      "host": "Voice Ai", "tag": "NEWS", "date": "2026-09-22" }
  ],
  "air": {
    "2026-09-22": ["intro.mp3", "digest.mp3", "music.mp3"],
    "2026-09-23": ["intro.mp3", "show.mp3"]
  }
}
```

### Инструменты сборки

Под очередью эфира живёт панель редактора:

- **Собираю эфир на** — выбор дня, включая будущий. Пустой день открывается
  только редактору, чтобы было куда складывать.
- **Взять из фонотеки** — вся библиотека с поиском по названию, описанию и
  ведущему и с фильтром по рубрикам. Рубрики строятся сами по тому, что реально
  загружено. Записи, уже стоящие в этом дне, помечены и не добавляются дважды.
- **Повторить прошлый эфир** — список прошлых выпусков с датой и числом записей.
  Копируется состав, а не ссылка: дальше дни живут независимо.
- **Взять за основу** — та же операция, но прямо из архива, когда вы разглядываете
  удачный выпуск.
- **Готово, эфир собран** — дожидается, пока все правки долетят до GitHub, и
  подводит итог: сколько записей, сколько минут, когда это увидят слушатели.
- **Очистить день** — убирает сборку целиком. Файлы не трогаются никогда.

Если в целевом дне уже что-то собрано, страница спрашивает: заменить, дописать
в конец или отменить. Записи, выходившие раньше, подписаны «повтор от 20 сентября».

Порядок меняется перетаскиванием за ⠿ или стрелками ↑↓ и сохраняется **в программу
этого дня**, не затрагивая остальные.

### Два разных удаления

Это различие важно и сделано намеренно:

| Действие | Где | Что происходит |
|---|---|---|
| **Убрать из дня** | крестик в очереди | запись уходит из эфира этого дня, остаётся в фонотеке и в других днях |
| **Удалить из фонотеки** | красная кнопка в форме правки | файл стирается из репозитория, запись исчезает у всех и из всех дней |

Второе спрашивает подтверждение и честно предупреждает, в скольких днях запись
сейчас стоит.

### Будущее, черновик и материалы без даты

В интерфейсе редактора у материала три разные пометки, и смысл у каждой свой.

**Будущее.** День, новость или запись с датой, которая ещё не наступила, **слушателю не показывается вообще**: ни в ленте,
ни в календаре, ни в архиве, ни в поиске. Материал уже сохранён, открывать и править его не нужно: он появится у слушателей сам,
когда наступит дата. Такой материал помечен «будущее» (у дня пунктиром с синей рамкой, над очередью плашка
«Будущее: эфир на 23 сентября. Слушателям этот день пока не показывается»).

**Черновик.** Так помечена только **запись без даты** первого эфира. Слушателю она не видна и сама не появится: нужно открыть
запись и поставить дату.

**Без даты (у новости).** Новость без даты слушатели **видят** (она показывается без даты), поэтому это не черновик. Пометка
«без даты» напоминает редактору поставить дату, чтобы новость встала в ленту по порядку.

### Загрузка и правка

Аудио загружается прямо со страницы: название, ведущий, раздел, теги, день
первого эфира, описание. Дата заполнена — запись встаёт в эфир этого дня; дата
пустая — просто пополняет фонотеку. Карандаш у записи правит всё то же самое,
там же кнопка удалить запись насовсем.

**Сжатие в браузере.** Если перетащить видео или тяжёлый файл, страница предложит
сжать его в MP3 прямо на компьютере редактора: из видео берётся только звуковая
дорожка, на выбор три профиля — речь 64 кбит/с моно, речь 96, музыка 128 стерео.
Файл при этом никуда не отправляется: всё считается в браузере, в репозиторий
уходит уже готовый лёгкий MP3, и его длительность сразу попадает в фонотеку.
Надёжнее всего загружаются файлы до 25 МБ — после сжатия туда помещается часовой
выпуск. Кодировщик — [LAME](http://lame.sourceforge.net) (lamejs, LGPL), лежит
отдельным файлом `lame.min.js` и подгружается только когда нужен; слушатели его
не скачивают.

Новости публикуются такой же формой: заголовок, дата, время, текст, ссылка на
источник и его название, теги с подстановкой уже использованных, автор и отметка
«важная».

## Робот

В репозитории работает GitHub Actions — он срабатывает сам при каждой загрузке
файла в папку `audio`:

- добавляет новые файлы в фонотеку, вытаскивая название и длительность из тегов;
- **бережёт всё, что вы правили руками** — названия, описания, рубрики, даты;
- **сохраняет программу эфира по дням** и вычищает из неё ссылки на удалённые
  файлы, чтобы в дне не осталось записи-призрака;
- убирает из фонотеки записи, файлы которых удалили.

Ход работы виден во вкладке **Actions**, запустить вручную можно там же.

---


**`audio/manifest.js`** — та же программа эфира, что в `manifest.json`, но в виде
скрипта. Её берёт виджет, если чужой сайт не даёт ему прочитать JSON. Файл
обновляется в двух случаях: редактор пишет его сразу после каждой правки
манифеста, а робот — когда в `audio/` появляется новый mp3. Сам файл робота не
запускает.
## Форматы и ограничения

### Что играет

| Формат | Поддержка |
|---|---|
| **MP3** | везде, рекомендуемый |
| **M4A / AAC** | везде |
| **WAV** | везде, но файл в 10 раз тяжелее |
| **FLAC** | везде, очень тяжёлый |
| **MP4** | играет звуковая дорожка |
| **OGG / Vorbis** | нет в Safari |
| **Opus** | ограниченно в Safari |

### Лимиты GitHub

| Ограничение | Значение |
|---|---|
| Один файл через сайт | 100 МБ |
| Один файл через веб-интерфейс GitHub | 25 МБ |
| Размер всего сайта | 1 ГБ |
| Трафик | 100 ГБ в месяц |

> **Про место.** Git хранит все версии навсегда: удалённый файл перестаёт играть,
> но место продолжает занимать. При получасе эфира в день в качестве 96 кбит/с
> гигабайтный предел придёт примерно через два месяца. Поэтому лучше сразу жать
> записи в MP3 64–128 кбит/с. Когда станет тесно, аудио переедет во внешнее
> хранилище — в манифесте вместо имени файла можно указать полную ссылку
> `https://…`, страница это уже понимает.

### О чём стоит помнить

- «Сегодня» вычисляется по часам устройства посетителя, а не по московскому
  времени. Для коллеги в другом часовом поясе окно может быть сдвинуто на день.
- Страницы «Подкасты», «Шоу» и «Гайды» пока показывают свёрстанные вручную
  карточки, а не читают фонотеку. На сборку эфира это не влияет — в фонотеке видно

## Как обновлять сайт

`index.html` весит около 930 КБ — это уже за пределами того, что комфортно
вставлять в редактор GitHub. Поэтому файл **заливают, а не копируют**:

1. Открыть репозиторий → `Add file` → `Upload files`.
2. Перетащить `index.html` в окно браузера.
3. `Commit changes`.

Имя должно быть ровно `index.html` — если браузер сохранил как `index(1).html`,
сначала переименовать. Файл робота обновляется так же, но заходить надо внутрь
папки `.github/workflows`, иначе он ляжет в корень и не заработает.
